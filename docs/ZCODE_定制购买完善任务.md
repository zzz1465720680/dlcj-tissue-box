# 鼎立车眷纸巾盒网站：定制购买流程完善任务

日期：2026-09-24

## 用户目标

用户希望通过抖音、小红书宣传，把感兴趣的客户引导到网站，定制纸巾盒并购买。请在现有项目中完成实现和验证，不停留在设计建议。实际项目路径为 `G:\DLCJ\13_纸巾盒定制网站`。

ZCode Bridge 与配套委派技能已可用。当前尚待用户确认购买方式、真实价格、可售规格、交期和客服联系方式。首轮按“选款定制、生成完整方案、联系客服确认购买”完成可审阅版本；未配置客服时提供可复制、可下载的需求方案，并诚实说明尚未发送。未经确认，不编造经营信息，不显示虚假的下单或付款成功。

## 已核查的现状

- 首页 `app/page.tsx` 有主视觉、定制海报、细节及场景，没有产品规格、适配说明、购买流程、客服和订单入口。
- `components/studio.tsx` 支持主体、四角、口沿、侧标，以及材质、颜色、打孔、图案；支持预设、撤销重做、IndexedDB 草稿、PNG/JSON 导出和登录后的云端方案保存。
- 现有 `/api/designs` 只保存设计，不接收采购意向或订单；云端保存依赖 ChatGPT 登录。普通客户应可在不登录的情况下选择、查看、保存本机草稿和生成询价摘要。
- 当前 `db/schema.ts` 没有订单表。不能把现有设计保存接口解释成下单接口。
- 客户界面暴露“模型校对”；存在面向开发者的文案，如“根据你提供的实物和裁片建立”。
- 两个登录链接的静态 href 含 `/customizecustomize`，正常点击处理器使用另一个正确路径；需统一修复并验证直接打开链接的回跳。
- 模型尺寸 16 × 10.5 × 约 6 cm 只是建模参考，README 明确要求实测校准，不可直接宣称成品销售规格和抽纸容量。
- README 记录 revision7 GLB 约 18.2 MB、765740 三角面；现有加载提示没有字节进度，手机需加载反馈、失败重试和轻量选款路径。
- 首页主要海报为生成视觉素材，车内图为场景示意；实拍参考另在 `public/references`。不得把生成图称为实物拍摄、交付案例或用户评价。
- 已有样式及模型经过多轮调整，保留现有视觉风格，不重做整个网站。

## 优先完成：客户从兴趣到询价的完整路径

1. 首页首屏说明可以定制哪些部位，提供“选推荐配色”和“自由定制”两种入口，以及清晰的下一步购买说明。推荐配色卡应把所选方案带入定制页；如存在用户草稿，先保留草稿并让用户选择是否替换。
2. 增加产品信息区：经确认的成品尺寸、容纳抽纸规格、材质、配色、可定制范围、养护方式和适配/摆放说明。把实测规格和建模参考区分开。未确认信息集中在内部配置和待确认清单中，面向客户应诚实说明需要确认，不能显示虚构数据。
3. 增加四步流程：选款/设计 → 确认材料、可制作性、价格及交期 → 确认购买 → 制作交付。只有在经营信息与交易方式确认后，才能将后两步表述为可在线完成。
4. 定制页增加“确认方案/咨询这款”主入口。展示所有部位的材质、颜色、油边、缝线、打孔、侧标与图案说明，数量及需求备注；不得漏掉独立四角和自定义图案。生成可复制的中文询价摘要，保留 JSON 和多角度图下载；摘要和方案绑定，修改设计后及时更新，避免发送旧配置。
5. 暂定优先采用“方案确认后联系客服购买”的可运行版本，最终以用户答复为准。客服渠道真实配置后显示可用按钮；未配置时只提供“保存方案/复制需求”等真实可用功能，明确尚未发送，不能显示“商家已收到”。本地方案编号不得冒充商家订单号。
6. 如果用户选择网站接收询价，必须实现真实的服务端持久化和商家可读取的接收入口，并验证接收成功与失败。不能用 localStorage、日志打印、setTimeout 或固定成功结果冒充提交。不要先收集不必要的地址或个人信息。
7. 如果用户选择在线支付：先明确真实商品及计价、商户账户、支付服务、退款规则、履约和部署条件；不得伪造支付能力。只有接入并验证真实服务后才显示对应可交易入口，支付确认须以后端验证为准。

## 手机体验与可制作性

- 保留首页轻量，不在首页提前加载 Three.js/大模型；推荐配色、产品说明和询价入口无需 3D 加载成功也可使用。
- 3D 加载时先展示明确标为预览的静态图；能获取真实总量时显示真实进度，无法获取时显示阶段状态，不伪造百分比。
- WebGL 不可用或网络失败时保留轻量方案与导出/询价路径；不得反复提示客户修改浏览器设置才能继续。
- 客户先选推荐配色，再按需打开高级定制；手机主操作可见且不遮挡内容，触控旋转与页面滚动不冲突。
- 自由颜色和任意图案属于设计意向，必须明确需实物色卡及工艺确认，不承诺任意颜色、材质和图案均能制作。
- 移除客户主导航中的模型校对入口，保留内部校对页与现有文件；不要破坏原工具。
- 将开发者文案改为客户能理解的说明，保留屏幕色差与实物确认提示。

## 宣传内容与转化观察

- 产品细节以实物参考为依据，补充换纸/抽取展示的素材位置；没有真实视频时不要伪造实测结论。
- FAQ 回答尺寸适配、配色确认、图案可制作性、价格构成、交期、配送与售后如何确认。价格、时效和规则只使用商家确认信息，不擅自写“包邮”“几天发货”“终身保修”或绝对退换条款。
- 可保留合法来源参数，区分从抖音/小红书进入的访问。漏斗事件可包括进入定制、选预设、完成方案、点击联系；若没有统计服务，明确仅完成接入点，不冒充已有真实数据。不把联系方式和完整上传图案写进埋点。
- 中英文入口保持一致可用；若定制及购买说明仅支持中文，应在英文入口说明实际语言范围。

## 保护范围

- 不覆盖 `.blend`、revision7 GLB、原图和既有草稿；不降低已经确认的几何品质来凑性能结果。
- 保持 design version 1、部位编号、PNG/JSON 导入导出兼容性及 R2 用户隔离。新增采购信息独立建模，避免污染设计文件。
- 不读取或复制用户其他账号的凭据，不关闭认证、不公开已有私有设计。
- 不自动发布到公网、不修改 `.openai/hosting.json` 的访问范围、不绑定支付、不作费用承诺。先完成本地可审阅版本，列清部署及经营配置项。
- 保留用户已有改动，避免无关升级依赖或重建项目。

## 验收要求

1. 新访客无需账号完成“首页 → 推荐配色 → 调整 → 方案摘要 → 保存/复制需求”，无死链、假成功或未配置的可点击客服按钮。
2. 有既有草稿时选预设不会无声覆盖；刷新、返回首页再进入后可恢复；修改配置后摘要同步。
3. 默认四角联动、独立四角、图案、侧标、撤销重做、导入导出、原有云端保存权限仍正常。
4. 至少检查 390px 手机、窄屏和桌面排版，无横向溢出、遮挡或无法点击的主要操作；检查慢网络与模型加载失败路径。
5. 执行类型检查与生产构建，以及与改动相关的现有回归脚本；为新增提交/持久化功能验证输入校验、失败提示和真实接收，不写仅镜像实现的测试。
6. 输出最终修改清单、实际验证结果、桌面/手机截图、本地预览地址及剩余经营配置项；未实测的支付、线上存储或移动设备性能如实说明。
