# 定制咨询版：验收与商家配置

日期：2026-09-24

## 交付范围

在 ZCode 初稿上，由主控按用户授权直接修正并验收。当前是本地的「选款 → 定制 → 整理需求 → 联系商家确认购买」版本，不含在线支付、订单后台和自动向商家发送消息。未发布、未改变访问权限。

- 首页：推荐配色、设计选项、购买步骤、适配与配色 FAQ，中英文文案保持一致。
- 3D 工坊：保留原模型、部位编辑、图案、撤销重做、预设、设计保存与导出。
- 轻量入口：`/customize?preview=light` 不创建 3D 模型，可直接编辑并生成需求；静态图明确标为款式参考，不假装跟随当前设计变化。可切换到 3D。
- 咨询面板：完整部位摘要、数量、备注、文字复制、文字/JSON 文件与 PNG 效果图；展开可查看全部部位。
- 询价数据独立保存在 `dlcj-inquiry-v1`，不改变旧的设计结构及其本机/云端草稿。

## 修正的关键问题

1. 输入 2.5 不再被改写成25，而是保持输入并提示需填整数；0、空值、超过999等均被拒绝。
2. 复制和所有询价文件导出使用同一校验条件；导出函数本身也拒绝无效数量，不再默认替换为1。
3. 关闭咨询、返回修改配色和刷新页面均保留数量与备注；存储不可用时有明确提示。
4. 旧副本比较包含设计、数量和备注，任何有效变更均提示重新复制。
5. 无Clipboard API或权限被拒绝时，不宣称复制成功；微信号还会直接显示以便手动复制。
6. 图片导出等待真实生成结果，失败不显示保存成功；成功后有实际预览及保存入口。
7. 文字/JSON下载保留可再次保存的链接；提示只描述生成或发起下载，不保证浏览器已经写入某个目录。
8. 首页去除无依据的“两分钟”、库存和实物工艺已确认说法；纠正黑色款为珊瑚红封边，而非红色包角。
9. 商家事实集中到一处配置，首页与咨询面板共同读取。

## 商家资料填写

统一编辑 `lib/merchant-config.ts`，改完重新构建后生效：

1. **客服渠道**：填写 `contact.channels`。支持微信号、电话、邮箱、HTTPS链接；空配置或非法链接不显示按钮。微信入口只复制账号，并显示可手动复制的文本，不会自动发消息。
2. **已确认资料**：`facts.confirmed` 填入 `{zh: '中文事实', en: 'English equivalent'}` 对象。首页与咨询面板会一起展示。只写商家确认过的实际规格、材料、报价、工期等。
3. **待沟通事项**：`facts.pending` 使用相同中英结构，填写需要客户与商家核对的内容。不要把编辑器能预览的效果当作库存或可制作承诺。
4. 若更换为在线交易，必须另接真实订单、商户支付与履约服务。仅把 `purchaseMode` 改为 `online` 不会产生支付能力。

开始接单前仍需：真实客服、成品尺寸/抽纸适配、可售材料与图案工艺、价格与加价规则、起订量、交期、运费及售后规则。
